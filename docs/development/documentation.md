# Documentation rules

เอกสารแต่ละไฟล์มีเรื่องเดียว เพื่อให้ AI อ่านเฉพาะข้อมูลที่จำเป็นต่อหนึ่งงาน

## วิธีอ่าน

1. อ่าน AGENTS.md ที่ใช้กับโปรเจกต์ แล้วเปิด [index](../index.md)
2. เลือกเอกสารหัวข้อที่เกี่ยวข้อง 1–2 ไฟล์ ตามด้วย source และเทสที่ไฟล์นั้นชี้ไว้
3. ใช้ `rg` หา symbol ก่อนเปิด source ใหญ่; เพิ่มหัวข้อที่อ่านเมื่อพบ dependency จริง
4. เปิดผลทดสอบเก่าเฉพาะเมื่อเทียบหลักฐาน ไม่ใช้แทน source ปัจจุบัน

## วิธีเขียน

- `README.md` เป็นทางเข้า ไม่เกิน 40 บรรทัด
- `AGENTS.md` เป็นกติกาส่วนรวม ไม่เกิน 40 บรรทัด
- `docs/index.md` เป็นตารางชี้เรื่อง ไม่เกิน 80 บรรทัด ไม่ใส่รายละเอียดระบบหรือประวัติ
- หัวข้อทั่วไปตั้งเป้าไม่เกิน 120 บรรทัด ถ้ายาวกว่านี้ให้แยกตามหน้าที่และเพิ่มลิงก์
- ข้อกำหนดหนึ่งมีเอกสารเจ้าของเดียว ไฟล์อื่นชี้ลิงก์แทนการคัดลอก
- เอกสารระบบระบุ source และเทสที่เกี่ยวข้อง เพื่อให้ตรวจความจริงจากโค้ดได้
- แยก **ทำแล้ว**, **วางแผน**, **ตรวจจริงแล้ว**, **ยังไม่ตรวจ** ให้ชัด
- แก้เอกสารปัจจุบันในตำแหน่งเดิม Git เก็บประวัติ ไม่ต่อบันทึกรุ่นลงท้ายทุกไฟล์
- แผนอยู่ `planning/`; รายงานส่งมอบอยู่ `delivery/verification-<version>.md`
- กติกาเฉพาะระบบอยู่ในหัวข้อนั้น ไม่ขยาย AGENTS.md ด้วยรายละเอียดของทุกระบบ
- เพิ่มลิงก์หัวข้อใหม่ใน index และลิงก์ source ด้วย path สัมพัทธ์ภายใน repo

## การตรวจหลังแก้เอกสาร

ตรวจลิงก์ภายในทุกไฟล์ว่าเป้าหมายมีจริง ทุกหัวข้อเข้าถึงจาก index ได้ และไม่เกินขนาดที่กำหนด
รัน `git diff --check` ตรวจ whitespace ไม่ต้องรันเทส runtime หรือบิลด์ EXE สำหรับ MD-only
CI ข้าม push/PR ที่เปลี่ยนเฉพาะ `.md`; เมื่อมี source หรือ workflow เปลี่ยน CI ยังทำงานตามปกติ
